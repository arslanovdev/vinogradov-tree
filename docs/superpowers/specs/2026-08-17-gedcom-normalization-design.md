# Нормализация и контроль целостности GEDCOM

## Цель

Привести `public/fedorovka_family.ged` к устойчивой структуре GEDCOM 5.5.1 с явно документированными расширениями проекта, не потеряв биографии, цитаты, гипотезы, координаты и медиа.

## Исходное состояние

- 190 персон, 68 семей, 43 структурных источника.
- Одна невзаимная связь: `@I201@ FAMC @F65@`, но в `@F65@` нет `CHIL @I201@`.
- Три локально удалённых файла всё ещё упомянуты пятью `FILE`-ссылками.
- 51 текстовый источник записан как `1 SOUR текст`, минуя принятые `@Sxx@ SOUR` и `PAGE`.
- 18 персон не имеют `_CONF`.
- 107 датированных `BIRT`/`DEAT` не имеют `PLAC`; добавлять можно лишь документированное место.
- 219 физических строк длиннее 255 Unicode-символов, 239 пустых строк.
- Большинство `NAME` не использует GEDCOM-разделители фамилии; три альтернативных имени используют `TYPE` вместо пользовательского `_TYPE`.
- PNG и WebP нужны приложению и сохраняются как явно разрешённое расширение мультимедийного формата.

## Архитектура решения

### 1. Чистая библиотека аудита

Новый модуль `src/gedcom/audit.ts` получает текст GEDCOM и необязательный набор доступных медиафайлов. Он возвращает типизированные проблемы без доступа к файловой системе. Проверяются синтаксис строк, уровни, уникальность XREF, типы и существование ссылок, взаимность семей, циклы предков, структура `SOUR/PAGE`, `PLAC/MAP/LATI/LONG`, медиа, `_CONF`, длина строк и пустые строки.

CLI `scripts/validate-gedcom.ts` запускается через уже установленный `vite-node`, отвечает только за чтение рабочего файла и каталога `public/photos`, вызывает библиотеку и завершает работу ненулевым кодом при ошибках. Команда `npm run validate:gedcom` становится постоянным предохранителем.

### 2. Безопасная нормализация текста

Парсер получает поддержку `CONT` и `CONC`. Перед разбором физические строки сворачиваются в логические значения: `CONC` присоединяет текст без перевода строки, `CONT` — с переводом строки.

Чистый модуль `src/gedcom/normalize.ts` выполняет идемпотентные преобразования, а тонкий CLI `scripts/normalize-gedcom.ts` только читает и перезаписывает файл:

- удаляет пустые строки;
- нормализует `NAME` в `GIVN /SURN/`, если фамилия явно дана дочерним `SURN`;
- заменяет `TYPE maiden/adopted` под `NAME` на `_TYPE`;
- разбивает строки длиннее 255 символов дочерними `CONC`, сохраняя точное значение;
- преобразует текстовые источники записей в новые `@Sxx@ SOUR`, сохраняя исходное описание без потерь.

### 3. Ручные фактические исправления

- Добавить `CHIL @I201@` в `@F65@`.
- Восстановить три удалённых файла из последнего коммита.
- Проставить `_CONF` 18 персонам после оценки основания: A — документально подтверждено, B — семейные данные или частичная связка, C — гипотеза/тупик.
- Добавить `PLAC` только в тех событиях, где место буквально названо в источнике или биографии. Не выводить место смерти из места захоронения и не подменять неизвестное догадкой.

## Источники

Каждый проверяемый документ получает отдельный `0 @Sxx@ SOUR` с `TITL` и кратким `ABBR`. Персона или семья ссылается через `SOUR @Sxx@`; конкретная страница, запись и URL остаются в `PAGE`, если их можно надёжно отделить от идентичности документа. Устные семейные сведения остаются в `NOTE`.

Механическая миграция не должна объединять источники только по похожему названию. Потеря текста недопустима: если автоматическое разделение `TITL/PAGE` ненадёжно, исходная строка целиком остаётся в `TITL` и требует последующей редакторской детализации, но уже имеет устойчивый XREF.

## Совместимость

Файл продолжает объявлять GEDCOM 5.5.1. Пользовательские теги начинаются с подчёркивания: `_CONF`, `_TODO`, `_KIND`, `_TYPE`. PNG и WebP сохраняются, потому что конвертация 49 доказательных изображений создаст ненужные бинарные дубликаты и риск потери качества; валидатор считает эти форматы разрешённым расширением проекта.

## Проверка

- Юнит-тесты аудита на минимальных фикстурах.
- Красные тесты на текущем семейном GEDCOM до исправлений.
- Тесты свёртки `CONT/CONC`, включая сохранение пробелов и переводов строк.
- `npm run validate:gedcom` без ошибок.
- `npm test`, `npm run check`, `npm run build`.
- Финальная проверка всех добавленных `FILE` и взаимности семейных ссылок.

## Не входит в работу

- Добавление новых персон или родственных гипотез.
- Присвоение неизвестных мест по соседним событиям.
- Конвертация PNG/WebP в JPEG.
- Удаление отрицательных результатов из `docs/indexing-log.md`.
