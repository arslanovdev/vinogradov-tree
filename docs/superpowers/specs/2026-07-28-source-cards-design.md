# Исправление карточек источников — дизайн

## Цель

Показывать каждую строку `1 SOUR` GEDCOM одной карточкой источника. Точки с
запятой внутри строки являются частью библиографического описания и не должны
создавать дополнительные карточки. Источник «Красная книга» А. М. Бекина
нужно убрать из списка `SOUR` у Егора Назаровича Белова, сохранив оба скана в
`OBJE` и доступными в разделе документов.

## Подход

Изменение ограничивается двумя местами:

1. `src/model/detail.ts` перестаёт делить значение `p.sources` по `;` и
   передаёт каждое значение `SOUR` в `formatSource` ровно один раз.
2. `public/fedorovka_family.ged` теряет только строку `1 SOUR` с описанием
   «Красной книги» у `@I17@`. Следующие `OBJE` с файлами
   `photos/bekin_late_arrivals_list_p263.jpg` и
   `photos/bekin_belov_family_p268.jpg` не изменяются.

Эвристическое объединение уже раздробленных карточек не используется: оно
может ошибочно объединить независимые источники. Структурная граница GEDCOM
`1 SOUR` является однозначным правилом.

## Проверка

Добавляется регрессионный тест модели, который создаёт персону с одним
`SOUR`, содержащим несколько `;`, и проверяет, что `buildDetail` возвращает
один `SourceRef` с полным текстом в `detail`. Также тест проверяет реальную
карточку Егора: источник Бекина отсутствует, а два документа остаются.

После изменений запускаются `npm test` и `npm run build`, затем выполняется
проверка структурной целостности GEDCOM через существующий `validate` и
проверка наличия обоих файлов `OBJE`.
