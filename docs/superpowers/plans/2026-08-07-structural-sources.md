# Структурные источники GEDCOM: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вынести повторяющиеся архивные дела и книги из текстовых `1 SOUR`/`NOTE` в структурные записи `0 @Sxx@ SOUR` и привязать цитаты (`1/2 SOUR @Sxx@` + `PAGE`) к записям и фактам BIRT/MARR/RESI, сохранив работоспособность приложения.

**Architecture:** Реестр повторяющихся документов (архивные дела, книги, БД) сопоставляется с текстами цитат; скрипт `scripts/structural_sources.py` заменяет текстовые `1 SOUR <текст>` на `1 SOUR @Sxx@` + `2 PAGE <детали>` (под фактом — `2 SOUR` + `3 PAGE`) и добавляет SOUR-записи перед `TRLR`. Парсер приложения дополняется резолвингом XREF: `1 SOUR @Sxx@` (и `2 SOUR @Sxx@` под событиями) разворачивается в строку «TITL; PAGE» для существующего блока «Источники» в UI.

**Tech Stack:** Python 3 (скрипт миграции), GEDCOM 5.5.1, TypeScript/Vitest (парсер и тесты приложения).

## Global Constraints

- Источник данных — `public/fedorovka_family.ged`; приложение не должно менять карточки/биографии.
- Не удалять полезные отрицательные результаты поиска и исследовательские рассуждения из `NOTE`; удаляются только чистые «Источник: …»-хвосты, заменяемые структурной цитатой.
- Каждая созданная `@Sxx@` обязана быть определённой записью `0 @Sxx@ SOUR`; каждая использованная `@Sxx@` обязана существовать.
- Конкретные детали (лист, двор, строка, запись, URL) переносятся в `PAGE`, а не теряются.
- Библиографически разные издания с похожими названиями не объединяются (пример: Морозова/Сафонова, Уфа 2017 ≠ Щербаков, Саранск 2016).
- После изменений: `npm test` и `npm run build`; проверка целостности связей GEDCOM и наличия медиафайлов.
- Код приложения меняется только в части парсера SOUR (задача касается формата данных, который приложение отображает).

### Извлечение PAGE

Для каждого документа задан префикс-паттерн (см. код скрипта); остаток текста после префикса нормализуется (удаляются ведущие `—`, `:`, `;`, пробелы) и становится `PAGE`. Если остатка нет — `PAGE` не выводится.

### Привязка к фактам

- **FAM**: цитата с маркером брака (`брак|венчан|жених|невеста|поручител`) и событием `1 MARR` → `2 SOUR @Sxx@` + `3 PAGE` под MARR. Иначе — `1 SOUR @Sxx@` на уровне FAM.
- **INDI, BIRT**: в цитате есть маркер рождения (`рожд|родилс|р\.\s|м\.п\.|ж\.п\.`), субъект записи (имя после `запись №…:`/`№… [жм]\.п\.`) начинается с имени персоны (первое слово GIVN, нормализованное), и в клаузе субъекта нет роли `восприемник|воспреемник|поручител|крестн` → `2 SOUR @Sxx@` + `3 PAGE` под `1 BIRT` (если есть).
- **INDI, RESI**: в цитате есть год переписи (`1917|1926`) и у персоны есть `1 RESI` с этим годом в `2 DATE` → цитата под этот RESI.
- **Всё остальное** (РС, книги, БД, фотоархивы) — `1 SOUR @Sxx@` на уровне записи.

### Заметки-источники

Заметки вида `Источник по РС 1816/1820…` (F56/F57) целиком заменяются структурной цитатой `1 SOUR @S6@` + `2 PAGE <фрагмент>` (текст после «Источник по РС 1816/1820 и переезду в Кузьминовку:»).

Дополнительно (второй проход): из исследовательских заметок, где рядом со структурной цитатой остались инлайновые координаты архива, убраны только координаты — I17 (`Р-472, оп. 1, д. 560`), I132/I139/F46 (`д.4496`), F35 (`л.647, двор 51`). Рассуждения и отрицательные результаты сохранены; сами цитаты закреплены на записи/факте.
